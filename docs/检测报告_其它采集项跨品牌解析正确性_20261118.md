# 检测报告：其它采集项在各品牌手机上的解析正确性（2026-11-18）

## 一、结论

对温度之外的**全部 Android 采集项**做「全网规范核对 + 真机 dump 对账」后：

> **未发现需要修复的真实缺陷。** 电池、内存、刷新率、网络、GPU、FPS/jank、前台应用等各项，在当前非标准命名的 Samsung 真机上解析结果均正确；历史针对各品牌做的单位/字段兜底均到位。
>
> 发现 2 个**理论边界观察项**（`swlan0` 接口白名单、GPU 探针路径误命中），经取证判定在本机无实际影响、且不构成跨品牌数据错误，**本轮不改代码**（不为改而改）。

这与上一轮温度传感器不同：温度是确认的兼容性缺口（厂商 `mName` 不标准导致副标题空白），已修复；其它项没有同类问题。

## 二、检测方法

1. **清点**：`adb.js` 全部 `getXxx/parseXxx` 采集与解析函数、`__algo` 纯函数、采集入口 `collector.js`、测试覆盖映射。
2. **全网规范核对**：AOSP ThermalHAL/types.hal、社区多品牌 dump（Samsung/联发科/国产 ROM）、bytescope.dev 等，判断每项依赖的厂商字段是否标准化。
3. **真机 dump 对账**：用当前 Samsung SM-XXXX（`<DEVICE_SERIAL>`，非标准命名代表机型）抓取 8 类原始 dump，喂给项目解析纯函数，逐项核对输出。原始取证保存在 `release/_sensor_audit_20261118/`。

> 覆盖边界：真机只有一台 Samsung。其它品牌靠 AOSP 规范 + 社区多品牌 dump + 项目历史真机取证佐证，不能等同于在每一台品牌机上实跑。

## 四、观察项（非缺陷，本轮不改）

### O-1：`swlan0` 未进入网络接口白名单
- 现象：Samsung 软件 Wi-Fi 接口 `swlan0` 不匹配 `METERED_IFACE_RE`，被整机口径 `/proc/net/dev` 排除。
- 取证：本机 `swlan0` 的 rx/tx 字节**全为 0**，真实流量走 `wlan0`（rx 999991123 / tx 216394384），已被正确计入。
- 判定：无实际漏算。且主口径是**按 UID 的 netstats**（不依赖接口白名单），整机口径只是两级失败后的回退。放宽白名单反而有把虚拟接口重复计入的风险——保持现状。

### O-2：GPU 探针路径误命中
- 现象：`/sys/kernel/gpu/gpu_busy`（探针标为 `exynos`）在高通机上存在，会被 `splitProbeOutput` 归到 `exynos` tag。
- 取证：其值与高通 `kgsl_pct` 一致（均 17%）；且 `GPU_NODE_PROBES` 优先级中 `kgsl_pct` 在前，`getGpuUsage` 先返回它，误命中的节点永远排在后面不会被采用。
- 判定：无数据错误。属探针路径的宽松匹配，不影响取值。

## 五、历史修复有效性复核（均确认到位）

- **GPU 多厂商探测**：14 节点表 + 单次 head -v + root 兜底；未命中返回 null 不写 0。
- **电池单位**：`normalizeBatteryVoltageMv`（mV/µV/V 三档）、`normalizeCurrentMa`（`current_max` 量级为主判据 + 数值兜底）。
- **刷新率**：排除 `mDefault*` 常量（D-19）、`capRefreshRateToPanel` 钳制 framework 虚高 vote（D-21）、上界 480Hz。
- **网络**：三级降级 + `netScope` 标注 + set 语义正确求和 + 只取当前 bucket + 单调时钟 + 回绕写 null。
- **内存**：App Summary 优先 + 明细表回退 + TOTAL 取首数字（防取到 SWAP PSS）。
- **CPU**：合并单次 `/proc/stat` + 按核名配对（防热插拔错配）+ cpuinfo→scaling 频率兜底 + stale 写 null。
- **FPS/jank**：按表头名取列 + timestats 失败记忆 + deadline=max(vsync,P50) + no-frames 写 null。
- **共性防线**：速率类 dt 统一用单调时钟 `monoMs()`；未测量统一写 `null` 而非 0。
